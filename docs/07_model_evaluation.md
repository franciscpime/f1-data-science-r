
# Model Evaluation, Performance Metrics and Regression Diagnostics

## 1. Introduction

Model evaluation determines how accurately trained predictive models estimate Formula 1 finishing positions.

This stage is implemented in:

`scripts/04_evaluation.R`

The evaluation focuses on the 2024 validation dataset and compares the performance of the predictive models developed in the previous stage.

In addition to measuring prediction accuracy, the script investigates prediction errors, model assumptions, multicollinearity, influential observations, and differences in performance across drivers and races.

The main objectives are to:

- Calculate prediction errors.
- Compare Mean Absolute Error (MAE) and Root Mean Squared Error (RMSE).
- Compare predictive models with a baseline.
- Examine errors across drivers, races, starting grid positions, and race statuses.
- Visualise predictions and error distributions.
- Investigate multicollinearity.
- Analyse residual patterns.
- Test for heteroscedasticity.
- Identify influential training observations.
- Export evaluation results and diagnostic visualisations.

## 3. Understanding Prediction Errors

The project calculates the difference between actual and predicted finishing positions.

For the original linear regression model:

```r
error = position - predicted_position
```

### 3.1 Mathematical Definition

\[
e_i = y_i - \hat{y}_i
\]

Where:

- \(e_i\) is the prediction error.
- \(y_i\) is the actual finishing position.
- \(\hat{y}_i\) is the predicted finishing position.

### 3.2 Example

| Actual position | Predicted position | Error |
|---|---|---|
| 3 | 5 | -2 |
| 8 | 6 | 2 |
| 10 | 10 | 0 |

A negative error means the driver finished in a better numerical position than predicted.

A positive error means the driver finished in a worse numerical position than predicted.

Because smaller finishing-position numbers indicate better results, this interpretation is specific to the target variable.

## 6. Mean Absolute Error (MAE)

Mean Absolute Error measures the average absolute difference between actual and predicted values.

### 6.1 Mathematical Definition

\[
MAE = \frac{1}{n}\sum_{i=1}^{n}|y_i-\hat{y}_i|
\]

Where:

- \(n\) is the number of observations.
- \(y_i\) is the actual finishing position.
- \(\hat{y}_i\) is the predicted finishing position.

### 6.2 R Implementation

The general calculation is:

```r
mean(abs(position - predicted_position))
```

### 6.3 Example

Suppose the absolute errors are:

```r
c(2, 4, 3, 1)
```

Then:

```r
mean(c(2, 4, 3, 1))
```

returns:

```text
2.5
```

The model is wrong by an average of 2.5 finishing positions.

### 6.4 Interpretation

A lower MAE indicates better average predictive accuracy.

For example:

| Model | MAE |
|---|---:|
| Model A | 2.5 |
| Model B | 3.2 |

Model A has the lower average absolute prediction error.

However, MAE does not indicate whether the errors are predominantly positive or negative.

## 7. Root Mean Squared Error (RMSE)

RMSE measures prediction error while giving greater weight to large errors.

### 7.1 Mathematical Definition

\[
RMSE =
\sqrt{
\frac{1}{n}
\sum_{i=1}^{n}(y_i-\hat{y}_i)^2
}
\]

### 7.2 R Implementation

```r
sqrt(
    mean((position - predicted_position)^2)
)
```

### 7.3 Calculation Steps

1. Calculate the difference between actual and predicted values.
2. Square each difference.
3. Calculate the mean of the squared differences.
4. Take the square root.

### 7.4 Example

Suppose the errors are:

```r
c(2, -4, 3, -1)
```

The squared errors are:

```text
4, 16, 9, 1
```

Their mean is:

\[
\frac{4+16+9+1}{4}=7.5
\]

Therefore:

\[
RMSE=\sqrt{7.5}\approx2.739
\]

### 7.5 `sqrt()`

Calculates the square root.

**Syntax:**

```r
sqrt(x)
```

| Argument | Description |
|---|---|
| `x` | Numerical input |

### 7.6 MAE vs RMSE

| Metric | Main characteristic |
|---|---|
| MAE | Measures average absolute error |
| RMSE | Penalises larger errors more strongly |

Both metrics use the same units as the prediction target: finishing-position numbers.

A model with a relatively high RMSE compared with its MAE may have some particularly large prediction errors.

## 8. Baseline Comparison

The project compares the predictive models with a baseline.

The baseline predicts:

```r
mean(train_data$position)
```

for every observation.

This creates a constant prediction based on the average finishing position in the training data.

### 8.1 Why Compare Against a Baseline?

A baseline establishes a minimum reference level of performance.

It helps determine whether using grid position and historical performance features provides an improvement over a simple constant prediction.

### 8.2 Percentage Improvement

The project also calculates the percentage improvement relative to the baseline.

The general formula is:

\[
\text{Improvement (\%)} =
\frac{
\text{Baseline Error} - \text{Model Error}
}{
\text{Baseline Error}
}
\times100
\]

For example, if:

- Baseline MAE = 5.
- Model MAE = 3.

Then:

\[
\frac{5-3}{5}\times100=40\%
\]

The model reduces MAE by 40% relative to the baseline.

This is a relative reduction in the selected error metric, not a 40-percentage-point increase in classification accuracy.

## 12. Analysing Errors by Race Status

The project groups prediction errors according to race status.

Race status can indicate whether a driver finished normally or experienced an incident such as retirement.

The analysis uses grouped summaries of absolute prediction errors.

A representative structure is:

```r
validation_data |>
    group_by(status) |>
    summarise(
        mae = mean(abs_error)
    )
```

### 12.1 Purpose

This analysis investigates whether prediction accuracy differs across types of race outcomes.

For example, unexpected retirements may be difficult to predict using starting position and historical performance alone.

### 12.2 Interpretation

Higher MAE for a particular status means predictions were less accurate for observations in that group.

However, this does not prove that the status itself caused the prediction errors.

Also, race status is known after the race and is used here for evaluation, not as a pre-race predictor.

## 23. Correlation Between Historical Features

The project calculates:

```r

    train_data$prev_avg_position,
    train_data$recent_avg_position
)
```

This measures the linear association between cumulative and recent average finishing positions.

### 23.1 Why Examine This Correlation?

Both variables summarise historical finishing performance.

A strong correlation suggests that they may contain overlapping information.

This can be relevant when including both predictors in a linear regression model.

### 23.2 Interpretation

A high correlation between predictors does not necessarily mean that one of them must be removed.

## 24. Variance Inflation Factor (VIF)

The project uses VIF to investigate multicollinearity.

```r
vif(model)
vif(improved_model)
vif(recent_model)
vif(recent_points_model)
```

### 24.1 What Is Multicollinearity?

Multicollinearity occurs when predictor variables are strongly related to one another.

This can make it difficult to estimate the separate contribution of each predictor.

### 24.2 Mathematical Definition

For predictor \(j\):

\[
VIF_j=\frac{1}{1-R_j^2}
\]

Where \(R_j^2\) is obtained by regressing predictor \(j\) on the remaining predictors.

### 24.3 `car::vif()`

Calculates Variance Inflation Factors for fitted regression models.

**Relevant syntax:**

```r
car::vif(mod, ...)
```

| Argument | Description |
|---|---|
| `mod` | Fitted regression model |
| `...` | Additional arguments supported by the method |

### 24.4 Interpretation

A VIF of 1 indicates no linear association with the other predictors.

Higher values indicate increasing multicollinearity.

Thresholds such as 5 or 10 are sometimes used as informal guidelines, but they are not universal rules.

### 24.5 Project Results

Selected VIF results from the project are:

| Predictor | Original LR | Improved LR | Recent Points LR |
|---|---:|---:|---:|
| `grid` | 1.57 | 1.57 | 1.57 |
| `prev_avg_position` | 6.00 | 14.40 | 4.63 |
| `prev_avg_points` | 5.85 | 5.85 | — |
| `recent_avg_position` | — | 9.75 | — |
| `recent_avg_points` | — | — | 4.47 |

These results suggest that the improved model has stronger multicollinearity involving historical finishing-position features.

The recent points model has lower VIF values for its historical predictors than the improved model.

The evaluation script also calculates VIF for the recent position model.

The exported `model_vif.csv` contains the original, improved, and recent position model results; the recent points VIF calculation is performed separately.

## 25. Residual Analysis

A residual is the difference between an observed value and a fitted or predicted value.

For training observations:

\[
e_i=y_i-\hat{y}_i
\]

Residual diagnostics can reveal patterns not captured by the model.

### 25.1 Residuals vs Fitted Values

The project creates a residuals-versus-fitted plot for the improved linear regression model using validation observations.

The plot compares prediction errors against predicted values.

### 25.2 Interpretation

A random scatter around zero is generally more desirable than a strong systematic pattern.

Patterns may suggest:

- Model misspecification.
- Nonlinear relationships.
- Changes in error variance.
- Particular regions where predictions are less accurate.

### 25.3 Important Distinction

The project's validation residual plot uses out-of-sample prediction errors.

These are useful for investigating predictive behaviour.

They are not identical to the in-sample training residuals used in conventional regression assumption tests.

## 26. Q-Q Plot

The project creates a Q-Q plot for the improved model's validation errors.

### 26.1 Purpose

A quantile-quantile plot compares the observed error distribution with a theoretical distribution, typically the normal distribution.

### 26.2 Interpretation

If points approximately follow the reference line, the observed distribution resembles the theoretical distribution.

Strong deviations may indicate:

- Heavy tails.
- Skewness.
- Extreme observations.
- Departures from normality.

### 26.3 Limitation

A Q-Q plot does not independently establish that all linear regression assumptions are satisfied.

In this project, the plotted values are validation prediction errors rather than the training residuals used to fit the model.

## 28. Breusch–Pagan Test

The project uses the Breusch–Pagan test to investigate heteroscedasticity.

```r
bptest(improved_model)
bptest(recent_points_model)
```

### 28.1 What Is Heteroscedasticity?

Heteroscedasticity occurs when the variance of regression errors is not constant across observations.

For example, prediction errors might become more variable as fitted finishing positions increase.

### 28.2 Test Hypotheses

The Breusch–Pagan test commonly evaluates:

**Null hypothesis:**

\[
H_0:\text{Constant error variance}
\]

**Alternative hypothesis:**

\[
H_1:\text{Non-constant error variance}
\]

### 28.3 `lmtest::bptest()`

**Relevant syntax:**

```r
lmtest::bptest(
    formula,
    varformula = NULL,
    studentize = TRUE,
    data = list()
)
```

| Argument | Description |
|---|---|
| `formula` | Fitted model or model formula |
| `varformula` | Optional formula specifying variables used to model error variance |
| `studentize` | Whether to use the studentized version of the test |
| `data` | Dataset used when a formula is supplied |

The project supplies fitted model objects.

The other arguments use their defaults.

### 28.4 Interpreting the p-value

A small p-value provides evidence against the null hypothesis of constant variance.

For example, using a significance level of 0.05:

- `p < 0.05`: evidence against constant error variance.
- `p >= 0.05`: insufficient evidence to reject constant variance.

Failure to reject the null hypothesis does not prove that variance is perfectly constant.

### 28.5 Training vs Validation

The project's `bptest()` calls operate on the fitted regression models.

They therefore use information from the training data on which those models were fitted.

They do not directly test the distribution of the 2024 validation prediction errors.

## 30. Cook's Distance Threshold

The project uses:

```r

```

as a reference threshold.

### 30.1 `nobs()`

Returns the number of observations used by a fitted model.

**Syntax:**

```r
nobs(object, ...)
```

| Argument | Description |
|---|---|
| `object` | Fitted model object |
| `...` | Additional method-specific arguments |

### 30.2 Threshold Formula

\[
\text{Threshold}=\frac{4}{n}
\]

Where \(n\) is the number of observations used to fit the model.

This is a commonly used heuristic for identifying observations worth investigating.

It is not a formal rule requiring observations above the threshold to be deleted.

### 30.3 Project Implementation

The script:

1. Calculates Cook's distance for training observations.
2. Calculates the threshold.
3. Counts observations exceeding the threshold.
4. Identifies the ten observations with the largest Cook's distance values.
5. Exports influential-observation results.

These diagnostics concern training observations, not validation errors.

## 36. Main Findings

The completed evaluation supports the following observations.

### 36.1 Predictive Models Outperform the Baseline

All seven predictive models achieved lower MAE and RMSE than the baseline on the 2024 validation dataset.

This suggests that starting grid position and historical performance features contain useful predictive information.

### 36.2 Recent Points Model Performs Best on Validation

The Recent Points Linear Regression model achieved:

- MAE: 2.9058.
- RMSE: 3.8338.

These are the lowest errors among the compared models on the validation dataset.

### 36.3 Additional Predictors Do Not Always Improve Accuracy

The Improved Linear Regression model adds recent average finishing position to the original specification.

However, the improvement in validation error is small.

This demonstrates that increasing model complexity does not necessarily produce a meaningful improvement in predictive performance.

### 36.4 Multicollinearity Requires Attention

The VIF analysis indicates stronger multicollinearity in the improved model, particularly for the cumulative and recent average finishing-position predictors.

This may affect coefficient stability and interpretation.

### 36.5 Some Race Outcomes Are Difficult to Predict

The grouped error analyses and large-error observations help identify cases where the available predictors do not fully explain the finishing result.

Unexpected incidents and race-specific factors are plausible explanations, but require additional evidence to establish.

## 37. Evaluation Limitations

### 37.1 Validation Is Not Independent Final Testing

The models were compared using the 2024 validation dataset.

Because the validation results influence model selection, the same dataset should not be treated as an independent final test.

### 37.2 The 2025 Test Evaluation Is Not Yet Complete

The project has a separate 2025 test dataset.

However, the completed evaluation workflow does not yet contain a final independent comparison of all models using 2025 results.

### 37.3 Error Metrics Do Not Explain Every Prediction Failure

MAE and RMSE quantify prediction errors but do not identify their underlying causes.

### 37.4 Regression Assumptions and Prediction Accuracy Are Different Questions

A model may achieve relatively good validation accuracy while exhibiting diagnostic issues.

Likewise, satisfying common regression assumptions does not guarantee superior predictions on unseen data.

### 37.5 Finishing Position Is a Ranking

Finishing positions are ordered numerical labels.

Regression metrics treat differences between positions as numerical distances, which is a modelling simplification.
